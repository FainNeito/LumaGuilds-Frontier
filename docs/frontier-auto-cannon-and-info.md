# Automatic cannon attribution and guild info layout

Requirements: during raid hours, attribute TNT through a player-operated lever or button when the loaded redstone path can be traced, retain /raidarm as a fallback, do not assign nearby disconnected TNT, and hide and recenter the Allies item in Frontier guild info when alliances are disabled.

Implementation: observe uncancelled activation of an unpowered lever or button; trace connected horizontal redstone dust and correctly oriented repeaters plus adjacent TNT and TNT powered by the dust's supporting solid block. The traversal visits at most 1024 blocks, remains within 64 blocks of the control, never loads chunks, and declines attribution if the node limit is exceeded. Existing 60-second arming and TNT chain handling applies. Conflicting existing armer and automatic operator are treated as ambiguous rather than credited to the wrong player. Sloped wire, comparators, pistons, dispensers, wireless or other untraced circuits may still require /raidarm. The info menu consults the existing Frontier alliance limit; disabled uses centered Truces and Enemies, enabled retains Allies.

Verification: the first trace/layout regression compile failed before implementation. Focused tests cover graph cycles and bounds, disconnected TNT, player control attribution, conflicting operators, raid explosion behavior, both menu layouts and notification regression. The Shadow JAR built. On an isolated Snapshot 8 server using a signed-in native client, the player operated a lever with dust, a lever with a repeater, and a stone button with dust without using /raidarm; each real TNT explosion retained the player as source (cannon-probe/auto-controls.log). The guild-info screen was inspected with alliances both enabled and disabled; the latter showed only centered Truces and Enemies. The live Bloom server was not changed. This did not repeat a complete vault defeat and leaderboard-credit test using automatic attribution, nor prove all cannon designs or player clients work.

Additional end-to-end check: with the lab-only vault durability reduced to four, a signed-in Snapshot 8 player operated a lever and repeater without /raidarm. The attributed TNT destroyed AutoCannonTarget's vault, its claim and partition were removed, and LabGuild's persisted vault score increased from 6 to 7. Evidence: cannon-probe/auto-vault-raid.log. Bloom remained unchanged during testing.
